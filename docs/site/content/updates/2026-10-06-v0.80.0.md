## Upgrading from v0.79.0 {#actions}

This release has no breaking changes. Install it the way you installed the previous one, then run this from the project root:

```bash
agnostic-ai upgrade --requires
```

It pins `requires` and the schema URL to 0.80.0 and syncs. If you keep a range or minimum in `requires`, keep it and run `agnostic-ai sync` instead.

Built-ins are opt-in, so existing projects change nothing until you add `builtins:` to `agnostic-ai.yaml`. Once you enable one, its text ships inside the binary. A later release can change it, and `sync --check` then reports drift. Run `agnostic-ai sync` after each upgrade.

## What agnostic-ai changed

### Carry a task between tools

Add the `handoff` built-in and sync:

```yaml
requires: ">=0.80.0"
builtins: [handoff]
```

Ask the current tool to "write a handoff". It saves the goal, acceptance criteria, completed work, next steps, open decisions, and checks in `.agnostic-ai/local/HANDOFF.md`. Open another tool in the same checkout and ask it to resume. It reads the file, compares it with Git, and continues from the next steps.

After saving, the skill proposes durable learnings from the session, each with a scope and a diff. Nothing is written until you confirm. Project learnings go to `.agnostic-ai/rules/learnings.md` for the team, personal ones stay in the gitignored local folder, and global ones apply across your projects. `init` enables the skill for new projects. See [Session handoffs](@/docs/handoff.md).

### Snapshot Git state automatically

Add `handoff-hook` next to the skill to record a Git snapshot before compaction and at session end, and to show a resume notice at session start:

```yaml
builtins: [handoff, handoff-hook]
```

It supports Claude Code, Codex, Gemini CLI, Qoder CLI, and Factory. The snapshot in `.agnostic-ai/local/HANDOFF.auto.md` holds the branch, HEAD, `git status --short`, and the last five commit subjects. It never reads diffs, transcripts, or tool memory. Each tool's own hook trust settings still apply. See [Automatic handoffs](@/docs/handoff.md#add-automatic-git-snapshots).

### Faster checks and safer imports

When no files changed, `sync` and `sync --check` run 2 to 5x faster. `sync --check --against` is about 5x faster in repositories with more than 20,000 tracked files, so pre-commit hooks finish sooner.

An `@path` line inside a code fence now stays as written, and a one-line code span no longer hides the `@path` lines after it.

Full list: [v0.80.0 release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.80.0).

## What changed in the targets

**Kiro CLI V3 runs workspace prompts as slash commands.** Kiro CLI 2.27.0 and newer lists the prompts in [`.kiro/prompts/`](https://kiro.dev/docs/cli/chat/manage-prompts/) in slash-command completion. This release syncs command specs there and imports them back, keeping native `$ARGUMENTS` templates. Earlier releases did not write Kiro commands. See [Kiro commands](@/docs/targets/kiro.md#commands).

**Claude Code renamed its AGENTS.md plugin.** The setting that controls whether Claude Code reads `AGENTS.md` is now [`pluginConfigs["cc-plugin-agents-md@builtin"]`](https://code.claude.com/docs/en/settings-reference); before v2.1.285 the ID was `agents-md@builtin`, and later versions read either. agnostic-ai does not write this user setting, so nothing changes in synced output.

**Amp no longer documents the per-service `agent` field.** The [portals docs](https://ampcode.com/docs/orbs/portals) (checked 2026-10-06) list `cwd`, `port`, `env`, `health`, `portal`, `portals`, `review`, and `platforms` for `.amp/services.yaml`. agnostic-ai still passes any `x-amp.terminals` key through unchanged; the Amp page now lists only the documented keys.
