## Upgrading from v0.73.0 {#actions}

1. **Update the project requirement and any pinned schema before an installation that runs sync in `postinstall`.** Use the `v0.74.0` schema URL shown below when adopting new config fields. Preserve a deliberate minimum or range; `requires: ">=0.74.0"` permits newer releases, while `requires: "0.74.0"` pins this generator exactly. A v0.73 binary cannot parse exact pins or ranges, so install the required release when it reports AAI-004. (Two lines in the config.)
2. **Install the same release locally and in CI.** For a standalone prebuilt binary, run `agnostic-ai upgrade --version v0.74.0`, then `agnostic-ai --version`. For a project-local npm install, use `npm install --save-dev --save-exact agnostic-ai@0.74.0` and commit the package and lockfile changes. Run the local binary through `npx agnostic-ai` in that project. (One installation and version check per environment.)
3. **If CI installs dependencies or runs sync before checking committed output, change the check to `sync --check --against HEAD`.** Set the checkout's `fetch-depth: 2` so it can also compare outputs from the parent commit and identify leftovers after a spec deletion. For a pre-commit check, use `--against index`. (One command and one checkout setting.)
4. **Claude Code users with `outputs.claude.settings.taskOutputMaxChars` should remove that setting.** Sync no longer emits it and reports its removal because Claude Code dropped the setting with the TaskOutput tool. (One config entry.)
5. **Regenerate and stage the updated files together.** Run `agnostic-ai sync`, review its output, and stage the changed specs, config, and tracked outputs. Run `agnostic-ai sync --check --against index` before committing. (One sync and one staged-state check.)

## What agnostic-ai changed

### Keep every contributor on the same generator

`requires` now accepts an exact release or several version constraints. A binary outside that value stops before reading specs or rewriting files, including a binary newer than an exact pin. This lets a project make a generator upgrade a reviewed change rather than letting each contributor's installed version decide the output.

For a project pinned to this release, the config begins:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/Chemaclass/agnostic-ai/v0.74.0/docs/schemas/config.schema.json
version: 1
requires: "0.74.0"
```

Use `requires: ">=0.74.0 <0.75.0"` to allow a bounded range instead. AAI-005 names the matching installation command. When the executable comes from the project's `node_modules`, the remedy uses its package manager, such as `pnpm install`, so contributors restore the project's locked dependency.

### Check the staged files or the commit

A working-tree check can pass after a `postinstall` script repairs files that were committed stale. The new Git-state checks render the specs from the selected state and compare them with the outputs tracked in that state:

```bash
agnostic-ai sync --check --against index
agnostic-ai sync --check --against HEAD
```

The first command catches a regenerated file left unstaged. The second catches a bad commit even if an earlier CI step rewrote its working copy. Ignored outputs are skipped. A tracked output left behind after deleting a spec also fails when the generated header or the previous state's rendered bytes prove its origin, including a headerless `.claude/launch.json`.

For example, after installing the pinned CLI, a GitHub Actions job can check the commit with:

```yaml
- uses: actions/checkout@v7
  with:
    fetch-depth: 2
- run: agnostic-ai sync --check --against HEAD
```

`explain --inputs` also lists config, source, and included-file inputs for a hook manager's trigger rules. A review's `@README.md` dependency belongs in that list, even when it sits outside `.agnostic-ai/`.

### Keep an output record in fresh checkouts

Repositories that commit generated files can opt into a committed manifest:

```yaml
sync:
  output-manifest: true
```

A full sync writes `.agnostic-ai/outputs.lock` with generated paths and content sums. Commit it with the outputs. `sync --check` checks the manifest too, and fresh checkouts can identify a listed output whose spec disappeared without relying on the ignored `.sync-state`. `doctor --fix` can remove a proven, unedited leftover. An edited file remains for you to resolve.

Separately, `sync --keep-edits` now protects an uncommitted edit to a Git-tracked output even when a new worktree has no ledger. A plain sync still regenerates files, so hooks that need to preserve those edits must explicitly pass `--keep-edits`.

### Reuse environment specs in the Codex app

The environment fields added for Cursor and Claude Code in v0.73 now also generate the Codex app's `.codex/environments/environment.toml`. Add a spec such as `.agnostic-ai/environments/local.yaml`:

```yaml
name: local
target: codex
setup: pnpm install --frozen-lockfile
cleanup: docker compose down
dev-commands:
  - name: Docs
    command: [pnpm, dev]
    cwd: apps/docs
    icon: run
```

`setup` becomes the worktree setup script, `cleanup` the cleanup script, and each dev command an action button. `setup-windows` can supply a separate Windows setup script. The Docs action runs `cd apps/docs && pnpm dev`, so a command that worked in a monorepo subdirectory keeps that directory. `import codex` reads the environment file back.

Codex actions have no destination for `port`, `auto-port`, `env`, or `url`; sync reports those fields as having no effect. Use `setup` for dependency installation and `dev-commands` for actions, since Codex does not consume the older `install` or `terminals` fields.

### Keep review and import text intact

A review spec can now consist of a standalone `@path` line that inlines a project file. Codex import keeps hand-written sections such as `## Conventions`, `## Rules`, `## Skills`, and `## Agents` as rules and skips only the generated listings. Cursor import reads `.cursor/environment.json`, retaining its `//` comments as YAML comments.

Codex instruction linting also warns when the root and scoped `AGENTS.md` chain exceeds 32 KiB. Shorten the chain if the warning reflects the limit your Codex install uses; `lint.codex-chain-bytes` changes the lint threshold, not Codex's own loading limit.
