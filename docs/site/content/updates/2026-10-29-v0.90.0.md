## Upgrading from v0.89.0 {#actions}

Stop any running `agnostic-ai watch` process before you update the install or the project config. Installing the package does not run sync, but a project `postinstall` script, the automatic update offer, `agnostic-ai upgrade --requires` and `agnostic-ai sync` do. Make the changes below that apply to you before any of them.

- **Keep project paths inside the project.** Move specs out of `.git` and change output paths that leave the project or enter `.git`. Replace links that lead to either place. `gitignore.path: .git/info/exclude` still works. See [project path boundaries](@/docs/configuration.md#path-semantics).
- **Review pack names, sources and update jobs.** Pack commands reject unsafe names and Git sources. `packs update` now restores the exact recorded commits. Use `packs update --latest` to move them forward. Local packs outside the project need the printed `packs add` command. See [updating packs](@/docs/packs.md).
- **Move imported credentials into native user config or supported environment references.** Claude Code and Codex imports drop literal credentials and refuse older captured overlays that hold them. After you clean those files, run `import claude --overwrite` or `import codex --overwrite` to replace existing specs. Grok imports keep only the documented safe settings. See [credential handling](@/docs/spec-format/mcp-import.md).
- **Move OpenHands global servers before global sync.** Add them in Agent Canvas under **Customize > MCP Servers**, then start a new conversation. The next global sync removes servers it managed in `~/.openhands/mcp.json`, including identical hand-written entries it adopted. See OpenHands' [settings store](https://docs.openhands.dev/openhands/usage/settings/mcp-settings) (checked October 29) and [legacy cleanup](@/docs/targets/openhands.md#mcp) for what sync removes.
- **Review affected native rules and names.** For imported Cursor rules that had no activation keys, set `alwaysApply: false` in their portable specs to keep them off. Rename Vibe agents named `main`, in any letter case. On Windows, rename imported spec filenames that contain colons. Gemini commands such as `git:commit` now use nested output folders.
- **Save a hand-written Junie effort before you sync.** Portable `effort` now writes `.junie/config.json` and replaces the native value. Import it first, or set `x-junie.effort` to keep a Junie-only override.

Web API clients: switch edit and preview requests to `audience: "shared"` or `"personal"`. v0.90.0 still accepts `scope: "team"` or `"local"`, which is deprecated and goes away in the next minor release. See the [API reference](@/docs/cli-reference/inspect.md#api).

Install through your package manager. For a global npm install:

```bash
npm install -g agnostic-ai@0.90.0
```

`agnostic-ai upgrade --requires` sets the project's `requires` and editor schema URL, then syncs. It also replaces minimum or range requirements and local overrides. To keep a minimum or range, leave it as is and set the schema URL to `v0.90.0` yourself. See [upgrade options](@/docs/cli-reference/upgrades.md#upgrade).

Run `agnostic-ai sync`, review the diff and any saved edited files, then run `agnostic-ai sync --check` before you restart watch. When `gh` is installed and logged in, install scripts and standalone `upgrade` now verify the download's build provenance. See [release verification](@/docs/verify-a-release.md#build-provenance) for the checks and fallback rules.

## What agnostic-ai changed

### Edit one tool's settings and find native-only servers

Run `agnostic-ai serve --open` and open **Settings > What each tool gets** to change `model` or `effort` for one tool. Pick **Shared** or **Personal**, preview sync, and save. A personal override for one tool leaves the shared defaults for the others. Global settings open in a separate tab with a link back to the project. See [settings edits](@/docs/spec-format/settings.md#edit-scalar-settings-in-the-browser).

The **Tools** view lists MCP servers found only in a tool's own config, so you can pick which to import. Lifecycle stages start collapsed, show hook counts and commands, and support search. The sidebar scrolls with the page, and keyboard focus, mobile fields and empty states are easier to use.

### Keep edited files and recover sync state

Sync saves edited generated files before it removes them, and keeps the backups private and out of Git. Case-only output renames survive cleanup. A missing external adapter leaves its files and shared skill links in place. Global sync keeps text outside its instructions block and comments around hooks in JSON settings.

An invalid sync state gives a warning and a fresh state file, and sync skips unsafe recorded paths. On Windows, `sync --check --against` compares committed bytes, ignoring checkout line-ending changes. Plain checks explain line-ending drift and links checked out as ordinary files. Sync is about 25% faster in the project's 500-spec measurement. See [sync behavior](@/docs/cli-reference/sync.md).

### Preserve more native settings

- **OpenCode:** import keeps provider config, including per-model prompt cache lifetime. Providers with literal credentials are skipped with a warning. V2 agents keep their `temperature` under `request.body.temperature`.
- **Copilot:** import and sync keep repository `enabledPlugins` and `extraKnownMarketplaces` for CLI and cloud. Copilot and OpenCode projects are now detected from their root settings files alone.
- **Junie:** portable effort reaches `.junie/config.json` and imports back. A settings spec can give Junie its own value:

```yaml
name: defaults
model:
  junie: sonnet
effort:
  junie: high
```

Junie loads its default project file only in trusted projects. Effort needs a configured model, which can come from another config file, and a saved effort for that model wins. See the [Junie configuration reference](https://junie.jetbrains.com/docs/junie-cli-configuration.html) (checked October 29), [effort by target](@/docs/spec-format/settings.md#effort-by-target), [OpenCode settings](@/docs/targets/opencode.md), and [Copilot settings](@/docs/targets/copilot.md) for supported fields.

### Attach a preview and target hook behavior

Claude Code can attach a preview to a server you already run. In an environment spec selected for Claude Code:

```yaml
name: preview
targets: [claude]
dev-commands:
  - name: App
    url: http://localhost:3000
```

Sync writes `.claude/launch.json` without a start command. See [environment fields](@/docs/spec-format/environments.md#fields).

CodeBuddy prompt hooks now work on `Stop`, `UserPromptSubmit` and `PreToolUse` at project scope. Mistral Vibe `post_agent` hooks can match a specific agent. Subagent `active_model` needs Vibe 3.0.3 or later. See [CodeBuddy hooks](@/docs/targets/codebuddy.md#fields-and-limits) and [Vibe mappings](@/docs/targets/vibe.md#connections-settings-and-hooks).

Gemini commands with names such as `git:commit` write nested TOML files and import with their original names. Qwen accepts the same command names on Windows and refuses output filenames that Windows cannot create. Grok checks Git visibility once per sync check, however many rules you have, and `init` records the required instruction-visibility policy.

### Get actionable checks before syncing

A version mismatch offers next steps, and `upgrade` points out a remaining project pin. Config errors name the source file, line, key and expected shape. `doctor` fails on unknown targets and reports JSON findings. `lint` and editors catch specs a selected tool cannot write and hooks with nothing to run.

Claude Code sync also warns about settings that project scope ignores, hook events that cannot run their handlers, and models that global effort does not change. With `blockReadsOutsideWorkingDirectories` on, tracked case or look-alike local settings can no longer turn on repository auto memory. Personal memory keeps working through linked or short project paths.

See the [full release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.90.0) for the remaining fixes.

## What changed in the targets

### Repository defaults and model cache settings

GitHub's [October 28 announcement](https://github.blog/changelog/2026-10-28-github-copilot-in-vs-code-universe-releases/) brings repository plugin defaults in `.github/copilot/settings.json` to Copilot CLI and Copilot in the cloud. They are defaults, not an enforced policy. This release imports and keeps them. The [native configuration reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference#repository-settings-githubcopilotsettingsjson) explains marketplace sources and overrides.

[OpenCode 2.2.0, released October 27](https://github.com/anomalyco/opencode/releases/tag/v2.2.0), adds per-model prompt cache lifetime. Import keeps the provider block under `x-opencode.provider`. Set `provider.<provider>.models.<model>.settings.cache.ttl`, such as `1h`. It stays an OpenCode setting, not a portable cache field.

### Opt-in scheduled prompts in OpenCode

[OpenCode 2.2.1, released October 29](https://github.com/anomalyco/opencode/releases/tag/v2.2.1), adds scheduled prompts and an optional image-generation tool. Turn them on through `x-opencode`:

```yaml
name: opencode-schedules
targets: [opencode]
x-opencode:
  timezone: Europe/Berlin
  experimental:
    schedules: true
```

Create schedules with OpenCode's `/schedule` command. Schedule definitions stay runtime state. Image generation has its own `experimental.image_generate` switch. v0.90.0 writes these settings but does not import the experimental fields. See the [native schema](https://opencode.ai/config.json).

### Vibe settings for outside-folder access and invalid keys

[Vibe 3.0.3](https://github.com/mistralai/mistral-vibe/releases/tag/v3.0.3), released October 26 and checked October 29, has `outside_workdir: deny` and `strict_config: true`, and `x-vibe` settings can write them. `outside_workdir: deny` blocks access outside the folder except added directories and allowlisted paths. `strict_config: true` rejects unused config keys. See the [released configuration source](https://raw.githubusercontent.com/mistralai/mistral-vibe/v3.0.3/vibe/core/config/vibe_schema.py) for their limits.
