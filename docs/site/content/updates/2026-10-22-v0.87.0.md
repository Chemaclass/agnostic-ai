## Upgrading from v0.86.0 {#actions}

Stop any running `agnostic-ai watch` process before you update the install or the project config.

`lint --strict` now fails on overlay files that no tool reads, such as `.agnostic-ai/overlays/gemini.settings.json`. Check the [supported overlays](@/docs/spec-format/overlays.md), then rename or remove those files. Lint skips dot files, dot folders and top-level README files.

Existing commands now produce skill files on qualifying targets. Read sync's notes when tools share a skills folder: a tool that reads another tool's copy sees the skill even when the command's targets exclude it. Except on Codex, a command becomes a skill only when no other enabled tool writes the same skills folder. See [tools without commands](@/docs/spec-format/commands.md#tools-without-commands).

Install through your package manager. For a global npm install:

```bash
npm install -g agnostic-ai@0.87.0
```

For an exact `requires` pin, `agnostic-ai upgrade --requires` sets `requires` and the schema URL, then syncs. It also replaces minimum or range requirements and local overrides. To keep a range or minimum, leave it as is and set the schema URL to `v0.87.0` yourself. This release needs no spec-format migration from v0.86.0. See [upgrade options](@/docs/cli-reference/upgrades.md#upgrade).

Run `agnostic-ai sync`, review the diff, and run `agnostic-ai sync --check` before you restart watch. Release binaries use Go 1.27.3, which has the certificate verification fix [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809).

## What agnostic-ai changed

### Run commands as skills in more tools

Codex, Copilot, Zed, Windsurf and Crush now get a command as a skill you start yourself. Create a command as before:

```bash
agnostic-ai new command review-changes
agnostic-ai sync
```

Codex gets the skill under `.agents/skills/`, with its invocation policy in `agents/openai.yaml`. Copilot uses `.github/skills/`. Zed, Windsurf and Crush get their native invocation fields. With `outputs.codex.commands-dir` set, Codex keeps its earlier command output.

A skill spec or hand-written native skill with the same name wins over the command. These skills treat the text after the name as arguments, with no `$ARGUMENTS` or `$1` substitution. Sync names those limits. The [command reference](@/docs/spec-format/commands.md#tools-without-commands) covers invocation, native paths and collisions.

### Find why Claude cannot see a synced skill

`doctor` reports synced skills that `skillOverrides` hides, disables or reduces to a name. To see the settings entries for one skill:

```bash
agnostic-ai doctor
agnostic-ai explain .agnostic-ai/skills/deploy/SKILL.md
```

The report checks project-local, shared project and user settings, and marks entries that a higher file overrules. It does not read managed settings or command-line `--settings`. It reports invalid JSON and rejected values. `doctor --fix` can offer to remove matching entries from project-local settings. It leaves user and shared settings alone. See [Claude skill overrides](@/docs/cli-reference/check.md#claude-skill-overrides).

### Keep deliberate Windsurf invocation edits

When no other enabled target writes the Windsurf skills folder, you can remove `triggers` from a native skill file and run `agnostic-ai import windsurf --overwrite`, and the change now survives the next sync. Only Windsurf changes. Other tools keep the portable user-only restriction. A shared folder keeps the restriction, because sync omits `triggers` there too. Import also reads `outputs.windsurf.skills-dir` when set. See [Windsurf skills](@/docs/targets/windsurf.md#skills).

Claude MCP permission names keep their server scope when a name contains `__` or ends in `_`. Hook lint no longer rejects `SessionEnd` matchers on Claude Code or Codex. The [full release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.87.0) cover the smaller fixes and docs changes.

## What changed in the targets

Checked against the docs on October 22, 2026.

- **Claude Code ignores a sandbox exception in project settings.** From v2.1.305, project settings cannot set `sandbox.allowNestedUserNamespaces: true`. User, managed or command-line settings can, and it lets sandboxed code escape the sandbox. This release fixes the guide and adds no portable permission. [Claude sandbox setting](https://code.claude.com/docs/en/settings-reference#sandbox-allownestedusernamespaces).
- **Ellipsis reviews can use Gemini CLI.** The schema names the engine `gemini`, with models `gemini-4-argon` or `gemini-3.8-flash`. v0.87.0 writes and imports `x-ellipsis.reviewer.gemini`. These sessions use Ellipsis credits, and Ellipsis lists skills as unsupported for this engine. See the [Ellipsis reviewer mapping](@/docs/targets/ellipsis.md#first-review), [review schema](https://www.ellipsis.dev/docs/code-review/schema), and [Gemini CLI limits](https://www.ellipsis.dev/docs/harnesses/gemini).
