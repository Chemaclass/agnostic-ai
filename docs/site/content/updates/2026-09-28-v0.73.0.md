## Upgrading from v0.72.0 {#actions}

1. **If the project adopts the new config keys, update its requirement and any schema pin before an installation that runs sync in `postinstall`.** Use the `v0.73.0` schema URL below and `requires: ">=0.73.0"`. This release accepts only a minimum requirement; pin the installer or package dependency to get one exact binary. (Two config lines and the installation pin.)
2. **Install v0.73.0 locally and in CI.** For a standalone prebuilt binary, run `agnostic-ai upgrade --version v0.73.0`, then `agnostic-ai --version`. For a project-local npm install, use `npm install --save-dev --save-exact agnostic-ai@0.73.0`, commit its package and lockfile changes, and run the binary with `npx agnostic-ai`. (One installation and version check per environment.)
3. **Choose how a fresh checkout gets its instructions.** Keep selected kinds in Git with `gitignore.commit`, or install the checkout hook when those files stay ignored. After changing the policy, run sync and review the files and `.gitignore` before staging them. (One config block or one hook installation.)
4. **Resolve newly reported leftovers.** A fresh checkout without `.sync-state` now names old generated files that no spec produces. Remove each unwanted file, or list a deliberately hand-maintained path under `sync.unmanaged`, then rerun `sync --check`. (One decision per reported path.)
5. **If a Copilot `subagentStart` hook uses a tool-name matcher, change it to an agent-name pattern.** This release explains the actual match value and warns on an invalid regex; a tool matcher such as `Bash` does not select a `code-review` agent. (One matcher per affected hook.)
6. **Regenerate and review the result.** Run `agnostic-ai sync`, then `agnostic-ai sync --check`, and commit the changed specs, config, and tracked outputs together. (One sync and one working-tree check.)

## What agnostic-ai changed

### Commit the outputs that must exist before sync

`gitignore.commit` excludes whole kinds from the managed ignore block across every configured target:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/Chemaclass/agnostic-ai/v0.73.0/docs/schemas/config.schema.json
version: 1
requires: ">=0.73.0"
gitignore:
  enabled: true
  commit: [instructions, hooks]
```

With this policy, root and scoped instructions, rule outputs, and hook files remain visible to Git. Skill and other generated files stay ignored. Adding another target does not require another `allow` glob for its instruction files. A file shared by several kinds stays visible when any of its kinds is selected, such as a settings file that also carries hooks.

If previously committed outputs should now be ignored, `agnostic-ai sync --untrack` runs `git rm --cached` on the generated paths that are both tracked and ignored. Their working copies stay in place. Review and commit the resulting index changes. This is opt-in; an ordinary sync reports the tracked-but-ignored paths instead.

### Regenerate ignored files after checkout

Install the local checkout hook with:

```bash
agnostic-ai install-hook --post-checkout
```

Use `--shared` as well to write it under `.githooks/` and set `core.hooksPath`. The hook runs `agnostic-ai sync -q` from the worktree root after a branch or worktree checkout. It skips a single-file checkout and exits successfully when the CLI or config is absent.

The installed v0.73 hook runs plain sync, so it overwrites hand edits to generated files. A custom hook can use `agnostic-ai sync --keep-edits` to protect edits recorded against its last sync. That protection depends on `.sync-state`: a fresh worktree has no tracked-file fallback in v0.73, so move or save hand edits before its first sync. This release makes `--keep-edits -q` report each kept file, so a quiet hook still tells you what needs moving back into the specs.

### Set up Cursor worktrees and Claude preview servers

Add `.agnostic-ai/environments/dev.yaml` with the setup command and preview server your project uses:

```yaml
name: dev
targets: [cursor, claude]
setup: pnpm install --frozen-lockfile
dev-commands:
  - name: Docs
    command: [pnpm, dev]
    cwd: apps/docs
    port: 3000
```

Cursor writes `setup` to `.cursor/worktrees.json` as its `setup-worktree` command list. An optional `setup-windows` replaces it on Windows. Claude Code writes the Docs entry to `.claude/launch.json`, giving the preview server its command, working directory, and port.

These are different native features: Cursor reads the worktree setup fields, while Claude reads the preview-server fields. Claude worktree setup still needs a `WorktreeCreate` or `SessionStart` hook. `import cursor` reads worktree setup back, and `import claude` reads preview servers back. Lint accepts a YAML-only environment spec and checks malformed, unnamed, or duplicate dev-command entries.

### Give Codex the same scoped review guidance

Review specs now reach Codex as `## Code Review Rules` in root and scoped `AGENTS.md`. For example, `.agnostic-ai/reviews/backend.md` can hold:

```markdown
---
scope: backend
targets: [codex, cursor]
---

Check authentication before any database access.
Report a missing check with its request path and affected handler.
```

Sync puts this guidance in `backend/AGENTS.md` for Codex and `backend/.cursor/BUGBOT.md` for Cursor. Specs sharing one scope concatenate into that scope's review output. `import codex` reads the review section back. Since `AGENTS.md` is shared by several tools, its readers also see the emitted section; use a target filter to control whether the Codex section is emitted.

### See stale files without a local ledger

`sync`, `sync --check`, and `doctor` now report each leftover generated output even when a fresh checkout has no `.sync-state`, with the removal action for that path. A successful sync can still retain a leftover it cannot safely remove, so read those reports before assuming the directory is clean.

Import reruns also stop adding duplicate rules, and imported references point back at canonical `.agnostic-ai/` sources. Newly initialized configs pin their editor schema to the installed release, omit the default `sources` mapping, and create only source folders seeded by the selected scaffold.

The [target comparison page](@/docs/compare.md) shows two or three tools' supported spec kinds and generated paths side by side. The [v0.73.0 release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.73.0) contain the complete change list.

## What changed in the targets

### Factory: new permission rules, existing lists still accepted

Factory's docs, **checked September 28, 2026**, deprecate `commandAllowlist`, `commandDenylist`, and `commandBlocklist` in favor of `permissionRules`. The vendor page gives no announcement date, and the old lists remain accepted. **State: target extension.** agnostic-ai still maps portable `allow`, `ask`, and `deny` to those lists; native rules can be supplied through `x-factory.permissionRules`. Rules require identifiers, command-prefix tokens, and matching examples, so the portable string lists do not automatically become that new schema. [Factory safety controls](https://docs.factory.ai/enterprise/llm-safety-and-agent-controls)

### Copilot: subagent hook matchers select agent names

GitHub's hooks reference, **checked September 28, 2026**, says a `subagentStart` matcher is a regex matched against the whole `agentName`; an invalid regex prevents the hook from firing. The page gives no announcement date. **State: supported.** v0.73 updates the matcher guidance and reports invalid patterns. An affected hook can use `event: subagentStart` with `matcher: code-review` to select that agent, rather than a tool name. [GitHub matcher reference](https://docs.github.com/en/copilot/reference/hooks-reference#matcher-filtering)

### Cursor: Security Review is separate from Bugbot

Cursor announced Security Review on **September 23, 2026**; it was first recorded in the project's audit on September 28. Teams and Enterprise can enable it per repository from the dashboard for exploit-focused pull request review. **State: watch, no adapter output.** agnostic-ai's review specs write Bugbot's `.cursor/BUGBOT.md`. The announcement documents team rules for Security Review but gives no repository file where this tool could write them. [Cursor announcement](https://cursor.com/changelog/rollouts-and-security-reviewer)

### Codex CLI 0.158.0: OAuth client-secret connections

Codex CLI **0.158.0, released September 28, 2026**, adds `codex mcp add --oauth-client-secret` for MCP servers using pre-registered OAuth clients. **State: watch, native CLI setup.** This is upstream connection support, not a new portable secret field in agnostic-ai v0.73. The audit had not established a project config key for the secret, so this release makes no claim that syncing an MCP spec provisions it. [Codex release notes](https://github.com/openai/codex/releases/tag/rust-v0.158.0)
