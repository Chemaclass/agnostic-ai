## What changed {#changed}

<!-- target-capability:cap-manual-only-skill-invocation:start -->
{% signal(status="safety", targets=["Claude", "Crush"]) %}
### Sensitive skills can be manual-only

Claude and Crush now share the same `disable-model-invocation: true` contract. It prevents the model from choosing a skill while keeping explicit user invocation available. agnostic-ai can preserve it through target extensions today, but cannot state the safety intent once.

**Vendor evidence.** Claude says, "Only you can invoke the skill." [Claude skills](https://code.claude.com/docs/en/skills). Crush says these skills "can still be invoked manually by users." [Crush repository](https://github.com/charmbracelet/crush).

**Repository evidence.** The shared [spec entry has no portable invocation field](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/spec/spec.go#L44-L79). Target extensions carry the value instead.
{% end %}
<!-- target-capability:cap-manual-only-skill-invocation:end -->

<!-- target-capability:cap-agent-mcp-scoping:start -->
{% signal(status="least privilege", targets=["Qoder", "Factory", "OpenHands"]) %}
### MCP access is moving inside the agent boundary

Three tools can narrow MCP access for an individual agent. Qoder accepts names or inline definitions, Factory uses a server-name allowlist, and OpenHands uses an inline server map. The shared goal is clear, but the portable shape is not.

**Vendor evidence.** Qoder supports "MCP servers" inside task-specific agent configuration. [Qoder subagents](https://docs.qoder.com/cli/subagent). Factory says, "Use `mcpServers` to limit which MCP servers a droid can reach." [Factory subagents](https://docs.factory.ai/harness/subagents). OpenHands says file-based agents can define "MCP server configurations inline." [OpenHands agents](https://docs.openhands.dev/sdk/guides/agent-file-based).

**Repository evidence.** agnostic-ai models agents through the same [generic entry](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/spec/spec.go#L44-L79). Qoder has a native mapping, Factory accepts target-specific metadata, and [OpenHands has no agent emitter](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/adapters/openhands/openhands.go#L105-L128). There is no shared agent-to-MCP contract.
{% end %}
<!-- target-capability:cap-agent-mcp-scoping:end -->

<!-- target-capability:cap-directory-scoped-skills:start -->
{% signal(status="context", targets=["Codex", "Cursor"]) %}
### A skill's directory now changes where it applies

[Codex scans nested skill directories](https://developers.openai.com/codex/skills/) from the working directory to the repository root. [Cursor says nested skills are scoped](https://cursor.com/docs/context/skills) to files inside their directory. Both agnostic-ai adapters flatten scoped skills to the root today.

**Vendor evidence.** Codex scans "every directory from your current working directory up to the repository root." [Codex skills](https://developers.openai.com/codex/skills/). Cursor says nested skills are "automatically scoped to files inside that directory." [Cursor skills](https://cursor.com/docs/context/skills).

**Repository evidence.** Both [Codex](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/adapters/codex/skill.go#L35-L42) and [Cursor](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/adapters/cursor/skill.go#L24-L30) build the destination from the root skills directory and the skill name, without the source scope.
{% end %}

<!-- target-capability:cap-project-extension-bundles:start -->
{% signal(status="ecosystem", targets=["Cline", "Amp", "Windsurf", "OpenCode", "Junie"]) %}
### Project plugins are becoming normal, not portable

Five tools now expose project extensions or plugins. Some copy executable code, some install package references, and some apply repository policy. agnostic-ai should represent the shared workflow only after it defines ownership and trust.

**Vendor evidence.** Cline supports plugins "per-project." [Cline plugins](https://docs.cline.bot/customization/plugins). Amp says project plugins "apply when you run Amp in that project." [Amp plugins](https://ampcode.com/docs/customize/plugins). Windsurf stores required and optional plugin policy in repository configuration. [Windsurf plugins](https://docs.devin.ai/cli/extensibility/plugins/overview). OpenCode calls `.opencode/plugins/` its "Project-level plugins" directory. [OpenCode plugins](https://opencode.ai/docs/plugins/). Junie describes extensions as "reusable bundles" for project-specific capabilities. [Junie extensions](https://junie.jetbrains.com/docs/junie-cli-extensions.html).

**Repository evidence.** The [ten shared spec kinds](https://github.com/Chemaclass/agnostic-ai/blob/8b4832a9494914bbfc0a13d7b0c8ae7aed6f5eb6/internal/spec/spec.go#L27-L38) do not include a plugin or extension bundle. Adding one before the trust model is clear would hide meaningful differences.
{% end %}

## Why it matters {#matters}

These are not cosmetic additions. A manual-only flag controls whether a model can start sensitive work. Agent-scoped MCP controls which systems and data a delegated agent can reach. Directory scope decides whether local instructions stay local.

The same pattern appears across the ecosystem. Vendors are moving more team policy into project files, but each uses a different path, schema, default, and trust boundary. A portable setup needs to keep the common intent while making native differences visible.

{% callout(title="The useful separation") %}
This briefing records upstream observations. The [target reference](https://agnostic-ai.org/docs/targets/) records current support. The [changelog](https://github.com/Chemaclass/agnostic-ai/blob/main/CHANGELOG.md) records what agnostic-ai has released.
{% end %}

## Where agnostic-ai is now {#position}

Manual-only skills work through target extensions. Qoder can preserve agent-scoped MCP through native agent metadata, Factory needs a target-specific field, and OpenHands has no file-agent emitter. Codex and Cursor currently lose directory scope when emitting skills. Project plugins have no shared spec kind.

These are audit observations, not shipped support. The target reference and release changelog remain the source of truth for what works today.

## What happens next {#response}

### Fix confirmed loss

- **Factory transport:** [Stop emitting undocumented `ws` MCP configuration.](https://github.com/Chemaclass/agnostic-ai/issues/809)
- **Scoped skills:** [Preserve directory scope in Codex and Cursor.](https://github.com/Chemaclass/agnostic-ai/issues/805)
- **Claude hooks:** [Keep `continueOnBlock` on prompt hooks.](https://github.com/Chemaclass/agnostic-ai/issues/804)
- **Index exclusions:** [Emit `.augmentignore` for Augment.](https://github.com/Chemaclass/agnostic-ai/issues/808)
- **Model settings:** [Extend project defaults to OpenCode and Junie.](https://github.com/Chemaclass/agnostic-ai/issues/806)
- **Kiro names:** [Preserve explicit custom-agent display names.](https://github.com/Chemaclass/agnostic-ai/issues/807)

### Decide the portable contract

- **Manual-only skills:** [Decide whether one shared field should preserve the invocation boundary.](https://github.com/Chemaclass/agnostic-ai/issues/811)
- **Agent MCP scope:** [Choose between a server allowlist, inline definitions, or both.](https://github.com/Chemaclass/agnostic-ai/issues/812)
- **Project extensions:** [Define the smallest safe shared outcome before adding a spec kind.](https://github.com/Chemaclass/agnostic-ai/issues/810)

- Codex and Cursor flatten directory-scoped skills.
