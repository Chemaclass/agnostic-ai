## What to do {#actions}

1. If you used `AGNOSTIC_AI_VERSION` with npm, pin the package instead, for example with `npm install -g agnostic-ai@0.64.0`.
2. If npm reports a missing optional platform package, run `npm install -g agnostic-ai --force --include=optional`.

## Shipped in agnostic-ai v0.64.0

### Changed

- `npm install agnostic-ai` no longer runs an install script to download a binary. The binary ships in a platform package (`@chemaclass/agnostic-ai-darwin-arm64` and five siblings) that npm picks by `os` and `cpu`. Installs work under `--ignore-scripts` and through npm's proxy settings. Offline installs need both packages in the cache or mirror. `AGNOSTIC_AI_VERSION` no longer applies to npm: pin the package version instead, as in `npm install -g agnostic-ai@0.62.0`. Both install scripts still honour it, and `AGNOSTIC_AI_BINARY` still points the wrapper at your own binary. A global copy missing its platform package now suggests `npm install -g agnostic-ai --force --include=optional`, which also overrides `omit=optional` in your npm config (#942).
- The release publishes the six platform packages before the parent and checks the version and dist-tag on all seven, so a partial publish fails the release instead of breaking installs on one platform. Each publish takes a `--tag` from its version (`-beta.1` to `beta`, `-rc.2` to `rc`, anything else to `next`), so a prerelease no longer takes npm's `latest` (#942).
- The Homebrew cask is no longer pushed from this repository and needs no secret here. `Chemaclass/homebrew-tap` updates its own cask every half hour with its workflow's `GITHUB_TOKEN`, after checking that all four archives resolve. The release still supports `HOMEBREW_TAP_APP_ID`/`HOMEBREW_TAP_APP_PRIVATE_KEY` and `HOMEBREW_TAP_TOKEN`, and writes a byte-identical file (#920, #943).
- Target audits reuse one issue index, load vendor references by target, and fit available worker slots; fix instructions load only when needed.

### Added

- `agnostic-ai lint` warns (LINT009) on an allowed `Bash(...)` rule with a `*` before the end of the command, such as `Bash(git * main)`. That rule also approves options inserted at that spot, on Claude Code and every target that translates it. Deny and ask rules are not flagged, since widening them only blocks or prompts more.
- Gemini writes and imports default-model settings, and Qoder writes HTTP and prompt hooks (#998, #1005).
- This repository now uses the three spec kinds it had not used itself: an `ignore` spec keeps build output, lockfiles, and local secrets out of ten targets' exclusion files, a `review` spec feeds Cursor Bugbot and Goose, and an `environment` spec serves Cursor, Amp, and OpenHands (#980).

### Fixed

- Claude rejects disabled project MCP servers and preserves manual rejection entries when re-enabled (#997).
- Import preserves Cline and Continue rule conditions, both Cline rule roots, and compatible Junie, Warp, and OpenCode skills (#999, #1000, #1001, #1002).
- Factory keeps scoped skills in their project areas, and Trae rejects agent names the tool cannot accept (#1004, #1006).

### Site

- The targets index records Cursor's default-on compatibility hooks and required `type: stdio` field (#1007).
- The landing page uses fewer words, and the targets lead names the four omitted spec kinds.
- The site builds on Zola 0.23.6 instead of 0.22.0. Templates and shortcodes moved to Tera 2 components, and three site tests that skipped on a mismatched local Zola now run on a current release (#970).
- The playground's kind picker describes the selected kind in one line and links to its section of the spec format. The landing names the four kinds its capability matrix leaves out, with a link each, and the README explains `review`, `environment`, and `ignore` instead of only listing them (#980).
- Generated-file tabs on the landing page stay inactive until `landing.js` initializes them, so readers without JavaScript see one real file (#977). `landing.toml` drops the unrendered `go` and `binary` installers, and a test now rejects unreachable installers (#991).
