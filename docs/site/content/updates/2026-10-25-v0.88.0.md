## Upgrading from v0.87.0 {#actions}

Stop any running `agnostic-ai watch` process before you update the install or the project config.

**Check your default targets before you install.** A project without a `targets` list now also syncs Pi, Qwen Code and Mistral Vibe. To keep your current selection, list the tools you want in `targets` before you update. An explicit list stays as it is. Import hand-written native config before you enable a new target, and follow its guide below for trust, model and output limits.

In development checkouts, replace `view authority` or `view overview` with `view` or `view --json`.

Install through your package manager. For a global npm install:

```bash
npm install -g agnostic-ai@0.88.0
```

After you install, `agnostic-ai upgrade --requires` sets `requires` and the editor schema URL, then syncs. It also replaces minimum or range requirements and local overrides. To keep a minimum or range, leave it as is and set the schema URL to `v0.88.0` yourself. See [upgrade options](@/docs/cli-reference/upgrades.md#upgrade).

No spec-format migration is needed from v0.87.0. Run `agnostic-ai sync`, review the diff, and run `agnostic-ai sync --check` before you restart watch. On OpenCode V2, regenerate affected agents so their tool restrictions survive when native V2 fields select that format. Review native edits before you import them over a source spec.

## What agnostic-ai changed

### Inspect setup in a bundled browser

Open the project or user config with no separate frontend install:

```bash
agnostic-ai view
agnostic-ai view --global
agnostic-ai view --json
```

Bare `view` finds the project in the current directory or its parents. Outside a project it opens the user config. The browser has Context, Authority, Tools, Lifecycle and Settings pages. Search finds source files, fields and cached MCP tool results. Each finding expands to details and a fix prompt you can copy. It has light and dark themes and works on narrow screens.

`agnostic-ai serve --open` starts the same local interface. Root help now groups commands by task. The [browser walkthrough](@/docs/inspect-configuration.md) shows how to inspect a warning and find its source.

### Review built-in changes before applying them

A project built-in switch previews the source edit and the generated changes for every configured target. Apply writes the reviewed files, and one undo restores the previous files and permissions. Pending source updates join the preview when files are missing or recorded checksums prove ownership. Hand edits need review in the CLI, and changed inputs block a stale apply or undo.

Run a first sync before you use project previews. Undo lasts for the server session. Global switches save source config, so run `agnostic-ai sync --global` to apply it. See [saving changes and undo](@/docs/cli-reference/inspect.md#serve) for recovery and memory-migration limits.

### Compare saved verifier outcomes

With `verify.command` set, save an external check before and after you change an instruction:

```bash
agnostic-ai verify --target codex --evaluation smoke-v1 --record before.json
# Edit the instruction and regenerate configuration.
agnostic-ai sync
agnostic-ai verify --target codex --evaluation smoke-v1 --record after.json
agnostic-ai verify compare before.json after.json
```

A record keeps the command outcome, duration, detected CLI, configured model and harness fingerprint. A pass followed by a failure reports a regression. Records with a changed or unknown evaluator, or a different evaluation ID, cannot be compared. If saving fails, a failed evaluation keeps its exit code, and a passed one exits 1. Result files are private, and replacing one needs `--overwrite`. The [verification reference](@/docs/cli-reference/check.md#record-and-compare-runs) defines identity boundaries, JSON, and exit semantics.

### Use six more native targets

Pi, Qwen Code and Vibe join the defaults. Grok Build, Kimi Code CLI and CodeBuddy Code are opt-in:

| Target | What sync writes, and the limit |
|---|---|
| [Pi](@/docs/targets/pi.md) (`pi`) | Instructions, skills, prompt commands, MCP and model settings. Native project settings need trust. Portable lifecycle hooks and tool restrictions have no native mapping. |
| [Qwen Code](@/docs/targets/qwen.md) (`qwen`) | Instructions, agents, skills, commands, MCP, hooks, settings and ignores. Use native exclusions to block inherited MCP servers with the same name. |
| [Mistral Vibe](@/docs/targets/vibe.md) (`vibe`) | Project and user instructions, subagents, skills, MCP, hooks and model settings. Host sandbox or agent-socket mode does not load the project's `.vibe` config. |
| [Grok Build](@/docs/targets/grok.md) (`grok`) | Project and user config. Keep instructions readable with `gitignore.commit: [grok:instructions]`. You still grant native trust and approve hooks. |
| [Kimi Code CLI](@/docs/targets/kimi.md) (`kimi`) | Instructions, agents, skills, MCP, and some user settings and hooks. Project hooks need a separate data-root export. Scoped shell restrictions have no mapping. |
| [CodeBuddy Code](@/docs/targets/codebuddy.md) (`codebuddy`) | Native config, with limits on agent names and tool restrictions. Root MCP output needs an explicit override. Sync does not grant native trust. |

### Preserve policy and audit evidence

OpenCode V2 agent fields keep tool restrictions and ordered permission rules through sync and import. Global import keeps an existing MCP spec when the native name differs only in case. Project checks skip built-in hooks that do not target the selected tools.

Vendor watch ignores known counter-only changes, labels historical additions as unreviewed, and catches edits to existing GitHub release notes. The first fetch against the old release-index format stays changed until an audit review advances it. The [full release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.88.0) cover the remaining target and docs fixes.

## What changed in the targets

Checked against primary sources on October 25, 2026.

- **Vibe 3.0.2 applies subagent controls and raises concurrency.** Released October 22, it fixes hooks inside subagents and applies custom tool policies and skill filters. Defaults rise to 32 alive and 32 concurrent subagents. agnostic-ai keeps native policy through `x-vibe` agent fields and accepts `x-vibe.max_subagents` and `x-vibe.max_concurrent_subagents` in settings. [Vendor release](https://github.com/mistralai/mistral-vibe/releases/tag/v3.0.2).
- **Codex 0.164.0 adds model-request observers.** The October 23 release's source has `PreModelRequest` and `PostModelRequest`, and agnostic-ai now accepts both event names. They only report: they cannot block or change a request, and need no matcher. [Release](https://github.com/openai/codex/releases/tag/rust-v0.164.0), [released implementation](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/hooks/src/events/model_request.rs).
- **Kimi Code CLI 2.3.1 fixes Windows trust failures and stale session locks.** Released October 23. Update Kimi itself to get these fixes. The new `kimi` target only manages config. [Vendor release](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai/kimi-code%402.3.1).
- **OpenCode V2 needs an explicit outside-project policy.** Found October 16 in the docs and rechecked October 25. V2 permission rules use the last match, and access outside the project is allowed by default. To keep the earlier prompt, add a native `external_directory` ask rule. v0.88.0 keeps generated V2 restrictions but does not pick that policy for you. [Migration guide](https://opencode.ai/v2/docs/migrate-v1#permissions-and-tools), [permissions](https://opencode.ai/v2/docs/permissions).
