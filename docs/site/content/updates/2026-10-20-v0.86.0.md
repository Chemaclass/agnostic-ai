## Upgrading from v0.85.0 {#actions}

Stop any running `agnostic-ai watch` process before you update the install or the project config.

**Check each Claude Code agent with a scoped capability before you install.** A value such as `can: [shell(git diff *)]` now writes `tools: Bash`, because Claude Code does not enforce command patterns in an agent's tool list. Add a `PreToolUse` hook to that agent that blocks other commands, or use settings deny rules, which apply to the main conversation and every agent. For the hook, first accept the interactive trust dialog for the exact folder that holds the agent file. Claude Code skips project agent hooks until then. Parent-folder trust and automatic `-p` trust do not count ([hook trust rules](https://code.claude.com/docs/en/sub-agents#hooks-in-subagent-frontmatter)). Sync reports each broadened capability, and `on-unsupported: error` stops on it. See [agent tool limits](@/docs/spec-format/agents.md#capabilities).

Install through your package manager. For a global npm install:

```bash
npm install -g agnostic-ai@0.86.0
```

For an exact `requires` pin, `agnostic-ai upgrade --requires` sets `requires` and the schema URL, then syncs. It also replaces minimum or range requirements and local overrides. To keep a minimum or range, leave it as is, set the schema URL to `v0.86.0`, review `agnostic-ai migrate --dry-run`, and run `agnostic-ai sync`. See [upgrade behavior](@/docs/cli-reference/maintain.md#upgrade).

Review and commit the generated diff, and run `agnostic-ai sync --check` before you restart watch. Look for these changes:

- Agents with top-level `maxTurns` or `background` now reach more tools. Check them against the [target mapping](@/docs/spec-format/agents.md#maxturns-and-background-by-target). Invalid types now stop validation and sync.
- Claude Code agents now always get `name` and `description`, with the name as the description when it is missing. An agent with an empty or unusable tool list is skipped with a note. Replace that list with the tools you want. `can: []` does not create an agent with no tools.
- New lint warnings flag likely credentials in more MCP fields and oversized Claude Code agent descriptions. With `lint --strict`, fix them.

## What agnostic-ai changed

### Set agent limits once

An agent can now use portable `maxTurns` and `background` fields:

```markdown
---
name: researcher
description: Finds relevant code and returns file paths.
can: [read, Grep, Glob]
maxTurns: 12
background: true
---

Find the relevant files and report what each one does.
```

Save it under `.agnostic-ai/agents/`. Claude Code and Qoder get both fields. Qoder background sessions need the native feature on. Junie gets `maxTurns`, Gemini CLI gets `max_turns`, Kilo Code and OpenCode get `steps`, and Cursor gets `is_background`. Other tools get a sync note. A matching `x-<target>` override wins, and import reads native values back. See [agent fields](@/docs/spec-format/agents.md#maxturns-and-background-by-target).

### Give an MCP server only to selected agents

Set `agent-only: true` on a server in `.agnostic-ai/mcps/`, then name it in an agent's `mcpServers` list:

```yaml
# .agnostic-ai/mcps/docs.yaml
name: docs
agent-only: true
type: http
url: https://mcp.example.com/mcp
```

```yaml
# In the agent's frontmatter
mcpServers: [docs]
```

Claude Code, Qoder, Kiro and OpenHands get the server definition inside the agent file. The server stays out of every project and user MCP file. Other tools get no copy, and sync says why. Agent files get stricter credential checks, because they are committed with the agent. See [agent-only servers](@/docs/spec-format/mcps.md#agent-only).

### Trace the sources behind a spec

```bash
agnostic-ai explain .agnostic-ai/rules/conventional-commits.md --layers
agnostic-ai explain .agnostic-ai/rules/conventional-commits.md --layers --json
```

The output lists the source files in resolution order, with each one's layer and whether it replaces or extends an earlier source. Replaced files stay visible, so you can trace a pack rule through a project replacement and a personal extension. It shows how project sources resolve, not whether a coding tool loaded the result. See [source layers](@/docs/cli-reference/inspect.md#debug-a-replaced-spec).

### Keep native settings through import

`import` keeps keys that a spec already has under `x-<target>` in that block, for every supported spec kind. A tool-specific setting no longer turns into a shared field that reaches other tools on the next sync. Kiro agent imports also keep key order and comments.

OpenCode agent permission rules keep their order, and restricted agents keep native V2 project limits. Factory MCP tool allowlists survive sync and import, and Ellipsis environments keep their `validate` hook. `import --global claude` imports Claude Code user permission rules into the home, and `sync --global` merges them back.

Sync notes now suggest a fix for dropped skill or agent fields and unsupported global agents. The JSON output includes those suggestions and global warnings. See the [full release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.86.0) for smaller fixes and documentation changes.

## What changed in the targets

These are documentation findings checked on October 20, 2026, not launch dates.

- **Claude Code inline MCP servers need folder trust.** The docs say the check applies from v2.1.238. Trust the project folder in an interactive session before you rely on an agent-only server. Parent-folder trust and automatic `-p` or SDK trust do not count. Sync writes the inline definition, and Claude Code decides whether to load it. [Claude Code trust rules](https://code.claude.com/docs/en/sub-agents#inline-server-trust).
- **Kiro CLI V3 honors global ignore files.** Its docs name `~/.kiro/settings/kiroignore` and Git's global exclusions, which apply only inside Git repositories. Set up those native files yourself for cross-project exclusions. This release fixes the guide, and sync still writes the project's `.kiroignore`. [Kiro ignore documentation](https://kiro.dev/docs/kiroignore/).
