## Upgrading from v0.76.0 {#actions}

1. **Stop `sync --watch` and migrate before installing.** Rules with narrow `globs` and no `alwaysApply` now ask for conditional loading. Add `alwaysApply: true` where you meant a rule to always load. Catch-all patterns stay always on. Unknown config keys and misspelled targets now stop config loading, in local overrides too.
2. **Align pins, then install.** Update exact `requires` and schema pins to `0.77.0`/`v0.77.0` by hand. Keep a deliberate minimum or range that accepts it. Do this before a package postinstall can sync. Pick your channel:

Prebuilt macOS binaries require **macOS 13+**. On macOS 12, use Go 1.26.8 or a newer 1.26 patch with `GOTOOLCHAIN=local go install github.com/chemaclass/agnostic-ai/cmd/agnostic-ai@v0.77.0`. [Other install channels](@/docs/installation.md).

**Standalone macOS 13+/Linux:** `agnostic-ai upgrade --version v0.77.0`.

**Project npm dependency:** `npm install --save-dev --save-exact agnostic-ai@0.77.0`.

MCP re-import turns every literal `env`/`headers` value into a reference, including non-secrets. Set the named variables or restore the non-secret literals. Continue IDE needs an ignored `.env`. Regenerate and review before you restart watchers:

```bash
agnostic-ai sync --plan
agnostic-ai sync
agnostic-ai sync --check
agnostic-ai lint
```

Use the local runner for project dependencies. Check `agnostic-ai --version` and commit pins, lockfile and tracked outputs together.

## What agnostic-ai changed

### Add a tool without losing tool-specific configuration {#add-a-tool-without-losing-native-configuration}

```bash
agnostic-ai use codex
```

`use` enables a target, adopts its existing config where supported, and syncs. It also initializes new projects. Import previews show conflicts before any write. Sync protects instructions you have not imported, backs up edits to generated files, and holds a project lock so two writers cannot collide. [Use and import](@/docs/cli-reference/start.md#use), [edit safeguards](@/docs/cli-reference/sync.md).

### Share sources outside the checkout

Absolute directories now work through import, preview, sync, validation and watch:

```yaml
sources:
  rules: /srv/team-specs/rules
  skills: /srv/team-specs/skills
```

Provide them on each machine. Imports write there; previews show destinations without writing. [Source paths](@/docs/configuration.md#sources).

### Use Codex aliases in model tiers

| Alias in a spec or tier | ID written by v0.77.0 |
|---|---|
| `sol` | `gpt-6.1-sol` |
| `luna` | `gpt-6-luna` |
| `astra` | `gpt-6-astra` |

```yaml
models:
  strong: {claude: opus, codex: sol, effort: high}
  balanced: {claude: sonnet, codex: gpt-5.6-terra, effort: medium}
  fast: {claude: haiku, codex: luna, effort: low}
```

Use `model: strong` in an agent spec. Aliases resolve to explicit IDs. Use an exact ID to pin a model. Terra uses its full ID in v0.77.0. [Models and aliases](@/docs/configuration.md#models).

### Keep credentials portable and checks useful

Project imports replace credentials with `${NAME}` references. Sync writes each reference in the syntax the tool reads, or omits an unsupported field with a note. Literals you write in a spec stay literal. Continue uses its secrets syntax and IDE `.env` files. `alwaysLoad` and `bareElicitationCapability` keep an explicit true or false for Claude. [MCP references](@/docs/spec-format/mcps.md#environment-references).

Strict validation catches config typos before any write. Rules load from narrow patterns where the tool supports it, and v0.76's selector union still applies. `sync --check --plan` now fails on drift. [Rules](@/docs/spec-format/rules.md#fields), [complete release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.77.0).

## What changed in the targets

- **Claude Code 2.1.287 (October 1):** MCP deferral and handshake flags round-trip in v0.77. Executable Mods can use existing supporting skill files and tool-specific settings. Read their code first: they run outside the Bash sandbox. [Release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.287), [Mods](https://code.claude.com/docs/en/plugins/mods/overview).
- **Claude Code 2.1.286 (September 30):** Claude Code requests eligible `verify` and `simplify` skills before commits. Sync your team checks, and enforce them with hooks or CI. [Check skills](https://code.claude.com/docs/en/skills#run-your-checks-before-each-commit).
- **Kiro (workflows September 30; resources checked October 2):** background workflows need native recipes, which agnostic-ai does not write. Resource lists still inherit context unless you turn off native inheritance. [Workflows](https://kiro.dev/docs/workflows/authoring/), [resources](https://kiro.dev/docs/custom-agents/configuration-reference/).
- **Cursor (references checked October 2):** you manage the `.cursor/config/bugbot.yaml` service policy in Cursor. agnostic-ai writes review instructions. Cursor finds shared `.agents/skills/` on its own, separate from compatibility imports. [Bugbot](https://cursor.com/docs/bugbot), [skills](https://cursor.com/docs/skills).
- **Copilot CLI (reference checked October 2):** repository hooks stay inside an enabled sandbox. Add native grants when hooks need more paths. [Hooks](https://docs.github.com/en/copilot/reference/hooks-reference).
- **Factory (reference/release checked October 2):** image-model selection works through tool-specific settings, but import does not read it back. Remove a declared marketplace at its project or organization source. [Settings](https://docs.factory.com/enterprise/hierarchical-settings-and-org-control), [release notes](https://docs.factory.com/changelog/release-notes).
- **Codex 0.160.0 (October 1):** Guardian context controls are experimental and off by default. Configure them only in native TOML. [Release notes](https://github.com/openai/codex/releases/tag/rust-v0.160.0).
