## Upgrading from v0.76.0 {#actions}

1. **Stop `sync --watch` and migrate before installing.** Narrow `globs` without `alwaysApply` now request conditional activation; add `alwaysApply: true` where unconditional loading was intended. Catch-all patterns stay always on. Unknown config keys and misspelled targets now stop loading, including local overrides.
2. **Align pins, then install.** Manually update existing exact `requires` and schema pins to `0.77.0`/`v0.77.0`; keep a deliberate minimum/range that accepts it. Do this before a package postinstall can sync. Choose your existing channel:

Prebuilt macOS binaries require **macOS 13+**. On macOS 12, use Go 1.26.8 or a newer 1.26 patch with `GOTOOLCHAIN=local go install github.com/chemaclass/agnostic-ai/cmd/agnostic-ai@v0.77.0`. [Other install channels](@/docs/installation.md).

**Standalone macOS 13+/Linux:** `agnostic-ai upgrade --version v0.77.0`.

**Project npm dependency:** `npm install --save-dev --save-exact agnostic-ai@0.77.0`.

MCP re-import converts literal `env`/`headers` values, including non-secrets, into references. Set the named variables or restore non-secret literals; Continue IDE needs an ignored `.env`. Regenerate and review before restarting watchers:

```bash
agnostic-ai sync --plan
agnostic-ai sync
agnostic-ai sync --check
agnostic-ai lint
```

Use the local runner for project dependencies. Check `agnostic-ai --version` and commit pins, lockfile and tracked outputs together.

## What agnostic-ai changed

### Add a tool without losing native configuration

```bash
agnostic-ai use codex
```

`use` enables a target, adopts its native config where supported, and syncs; it also initializes new projects. Import previews expose conflicts before writes. Sync protects unimported instructions, backs up generated-file edits, and uses a project lock to prevent competing writers. [Use and import](@/docs/cli-reference/start.md#use), [edit safeguards](@/docs/cli-reference/sync.md).

### Share sources outside the checkout

Absolute directories now work through import, preview, sync, validation and watch:

```yaml
sources:
  rules: /srv/team-specs/rules
  skills: /srv/team-specs/skills
```

Provide them on each machine. Imports write there; previews show destinations without writing. [Source paths](@/docs/configuration.md#sources).

### Use Codex aliases in model tiers

| Alias in a spec or tier | ID written by v0.77.0 |
|---|---|
| `sol` | `gpt-6.1-sol` |
| `luna` | `gpt-6-luna` |
| `astra` | `gpt-6-astra` |

```yaml
models:
  strong: {claude: opus, codex: sol, effort: high}
  fast: {claude: haiku, codex: luna, effort: low}
```

Use `model: strong` in an agent spec. Aliases resolve to explicit IDs; use exact IDs to hold a model steady. [Models and aliases](@/docs/configuration.md#models).

### Keep credentials portable and checks useful

Project imports replace credentials with `${NAME}` references; sync translates them to native syntax or omits unsupported fields with a note. Explicit spec literals remain literal. Continue uses its secrets syntax and IDE `.env` files. `alwaysLoad` and `bareElicitationCapability` retain explicit true/false for Claude. [MCP references](@/docs/spec-format/mcps.md#environment-references).

Strict validation catches ignored config typos before writes. Rule activation follows narrow patterns where supported, with v0.76's selector union still applying. `sync --check --plan` now fails on drift. [Rules](@/docs/spec-format/rules.md#fields), [complete release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.77.0).

## What changed in the targets

- **Claude Code 2.1.287 (October 1):** MCP deferral/handshake flags round-trip in v0.77. Executable Mods can use existing skill assets and native Settings; inspect their code because they run outside the Bash sandbox. [Release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.287), [Mods](https://code.claude.com/docs/en/plugins/mods/overview).
- **Claude Code 2.1.286 (September 30):** eligible `verify`/`simplify` skills are requested before commits. Sync team checks; use hooks or CI for enforcement. [Check skills](https://code.claude.com/docs/en/skills#run-your-checks-before-each-commit).
- **Kiro (workflows September 30; resources checked October 2):** background workflows need native recipes, which agnostic-ai does not emit. Resource lists still inherit context unless native inheritance is disabled. [Workflows](https://kiro.dev/docs/workflows/authoring/), [resources](https://kiro.dev/docs/custom-agents/configuration-reference/).
- **Cursor (references checked October 2):** `.cursor/config/bugbot.yaml` service policy remains native-managed; agnostic-ai writes review instructions. Shared `.agents/skills/` discovery is independent of compatibility imports. [Bugbot](https://cursor.com/docs/bugbot), [skills](https://cursor.com/docs/skills).
- **Copilot CLI (reference checked October 2):** repository hooks stay inside an enabled sandbox. Adjust native grants when hooks need additional paths. [Hooks](https://docs.github.com/en/copilot/reference/hooks-reference).
- **Factory (reference/release checked October 2):** image-model selection supports native Settings passthrough, without import round-trip support. Remove declared marketplaces at their project/organization source. [Settings](https://docs.factory.com/enterprise/hierarchical-settings-and-org-control), [release notes](https://docs.factory.com/changelog/release-notes).
- **Codex 0.160.0 (October 1):** Guardian context controls remain experimental and off by default, with native TOML configuration only. [Release notes](https://github.com/openai/codex/releases/tag/rust-v0.160.0).
