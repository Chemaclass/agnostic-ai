## Upgrading from v0.82.0 {#actions}

Stop any running `agnostic-ai watch` process before updating the installation or project config.

**Git and setup hooks now prefer the project installation.** If your project declares agnostic-ai in `package.json`, install that dependency before running its hooks. An existing exact package version must agree with `requires`; a global binary cannot replace a missing declared local installation. Update the dependency, lockfile and requirement together. See [project version checks](@/docs/cli-reference/maintain.md#project).

Install through your existing package manager. For a global npm installation:

```bash
npm install -g agnostic-ai@0.83.0
```

For an exact project config pin, `agnostic-ai upgrade --requires` updates `requires` and the schema URL to the installed version, then syncs. It also replaces minimum or range requirements and local overrides. To keep a deliberate minimum or range, retain that value, update the schema URL to `v0.83.0`, review `agnostic-ai migrate --dry-run`, and run `agnostic-ai sync`. Finish with `agnostic-ai sync --check`, then restart watch. See [upgrade behavior](@/docs/cli-reference/maintain.md#upgrade).

**OpenCode V2 hooks are optional and require macOS or Linux.** V1 remains the default. Select `x-opencode.plugin-api: v2` per hook when using V2; V2 cannot load V1 plugins. On Windows, use OpenCode V1 for generated hooks. Review [supported events and blocking behavior](@/docs/targets/opencode.md#opencode-v2-hooks) before switching.

## What agnostic-ai changed

### See which instructions cover a file

Claude Code and Codex now join Cursor in file-specific instruction reports. Use a configured project target:

```bash
agnostic-ai explain --file src/main.go --target claude
agnostic-ai explain --file src/main.go --target codex
agnostic-ai explain --context --target claude
```

The file report names source specs, planned output paths, selectors and reasons. It marks session-dependent discovery as unknown, including Codex's launch directory. The context report ranks startup sources by words and bytes and separates on-demand bodies. These reports describe planned project configuration; word counts are estimates, not model tokens or observed session context. See [instruction and context reports](@/docs/cli-reference/inspect.md#explain-a-source-file).

`compare claude codex` now includes hooks, MCP connections and portable permissions. It shows where a field is preserved, translated or unsupported before you move tools. Connection values are hidden, and permission summaries hide recognized credentials. See [comparison coverage](@/docs/cli-reference/inspect.md#compare).

### Check the project version before starting work

The new `project` command chooses the installed project binary, checks its version requirement, and runs sync or a delegated command. To stop a cached environment before startup when configuration is missing or stale:

```bash
set -e
agnostic-ai project --check
agnostic-ai project -- doctor --scope project --check-references
```

The second check covers configured targets and generated skill links without approving local hooks. If the installation is missing or mismatched, `agnostic-ai project --bootstrap` uses the committed npm or pnpm lockfile to repair it and regenerate output. Install v0.83.0 through your package manager first: v0.82.0 cannot run this helper. Failed checks now retain command errors and timeout reasons. See [project readiness](@/docs/cli-reference/maintain.md#project-readiness).

### Keep worktree setup and handoff notes in the right checkout

Claude Code handoff hooks now use the tool's event data to find the active checkout. To rerun changed environment setup in an existing linked worktree, sync there first, then run:

```bash
agnostic-ai hook worktree-refresh --repo /path/to/main --worktree /path/to/linked
```

Only that worktree's setup marker resets. The separate `hook worktree-remove` helper removes a registered clean worktree under an explicitly allowed root; changed, ignored or locked contents stop removal. See [refreshing setup](@/docs/cli-reference/maintain.md#hook-worktree-refresh) and [safe removal](@/docs/cli-reference/maintain.md#hook-worktree-remove).

### Adopt OpenCode V2 and Copilot user hooks

For OpenCode V2 on macOS or Linux, a tool-specific before-tool check can use:

```yaml
name: guard-shell
targets: [opencode]
event: PreToolUse
matcher: shell
command: .agnostic-ai/scripts/guard-shell.sh
x-opencode:
  plugin-api: v2
```

Create the executable script first. A before-tool command exiting 2 blocks the operation; other failures are logged and continue. Commands receive the tool's event JSON on stdin. Timeouts and plugin unload stop owned processes. This route has no portable `on` mapping or structured stdout decisions. See [OpenCode V2 hooks](@/docs/targets/opencode.md#opencode-v2-hooks).

OpenCode sync and import also preserve `disable-model-invocation: true` and native invocation metadata. V2 keeps a manual-only skill out of the model's available list while allowing explicit loading; V1 does not enforce the flag. Import preserves the V2 MCP envelope, disabled servers, separate timeouts and servers added by hand. See [OpenCode configuration](@/docs/targets/opencode.md).

Copilot user hooks are now preserved through `agnostic-ai import --global copilot` and `agnostic-ai sync --global --only copilot`. Sync keeps matching handwritten handlers in their original files to avoid duplicate execution, and creates them in the managed file on a fresh machine. See [Copilot hooks](@/docs/targets/copilot.md#hooks).

### Keep source edits and diagnostics usable

`new` now creates templates for all ten spec kinds. `import reconcile` plans later skill edits, assets and deletions against the source spec files after a migration; review and apply that plan separately. See [scaffolding](@/docs/cli-reference/start.md#new) and [reconciliation](@/docs/cli-reference/start.md#import-reconcile).

VS Code shows saved source errors in Problems, clears resolved findings, reports failed drift checks and keeps checks current. Staged checks do less repeated work, typo checks use less memory, and `sync --json` remains valid on a fresh shared-skill setup while reporting unchanged links as skipped.

`explain` reports when Claude Code or Amp chooses a home skill over a same-name project skill. `doctor rtk --command` previews RTK rewrites and declared approval changes; it cannot establish live approval. Credential previews hide more secrets, Cline hook tool names remain literal data, and build downloads and npm releases receive stronger verification. Full list: [v0.83.0 release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.83.0).

## What changed in the targets

**OpenCode V2 needs a different hook plugin format.** The [migration reference](https://opencode.ai/v2/docs/build/plugins/migrate-v1), checked October 11, 2026, says V1 plugin code cannot run in V2. The opt-in mapping above uses V2's format, verified against 2.0.26; generated V2 hooks remain limited to macOS and Linux. Its [skill reference](https://opencode.ai/v2/docs/skills), checked the same day, also documents manual skill selection. The preserved flag controls automatic availability while keeping explicit loading possible.

**Copilot CLI combines user and project hooks.** Its [hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference), checked October 11, 2026, documents user files under `~/.copilot/hooks/` or `$COPILOT_HOME/hooks/`. The global sync and import commands above now cover that route. The cloud agent uses repository hook files instead.


**Kiro can retain learned repository context.** [Kiro CLI 2.29.0](https://kiro.dev/changelog/), announced October 9, 2026, adds Memory to local V3 sessions. Use `/memories`, then `config`, to choose read/write, read-only, or off. Writes require a trusted workspace; automatic updates require read/write. The [memory guide](https://kiro.dev/docs/memory.md), checked October 11, describes repository-scoped records, while IDE support remains coming soon. Configure this in Kiro: agnostic-ai does not sync or import its learned records.

**Trae can group work across multiple repository paths.** [Trae v3.6.0](https://www.trae.ai/api/changelog), dated October 8, 2026, adds an Agent-window project that mounts multiple paths and groups its tasks, file tree and search. Set up these workspaces in Trae. The announcement gives no project configuration file to sync, and agnostic-ai does not create or import the mounts.
