## Shipped in agnostic-ai v0.60.0 {#shipped}

### Added

- The site has a keyboard-friendly search (Cmd/Ctrl+K or /) over every guide, target page, and update, with results that link to the matching section. The index is generated at build time and loaded on first use.
- The landing page embeds the talk demo behind a click-to-play poster; YouTube loads only after the click, through youtube-nocookie.com.
- The landing page states what agnostic-ai is for: four principles, and an answer to "why not just symlink one file?".
- The docs cover agent memory and the memory boundary: the three `memory` scopes an agent spec can set, which one git carries, and why the Claude Code and Qoder auto memory stores are tool-owned and never synced. A new `memory-curator` skill, scoped to those two targets, audits a store in place and proposes merges and deletions, applying nothing until you confirm. `agnostic-ai init --demo` seeds the skill in a new project (#842, #843).

### Changed

- The targets reference is one page per target at `/docs/targets/<id>/`, with the index keeping the capability matrix and the cross-target notes. Older deep links such as `#claude-code-claude` redirect to the new page.
- Every target page carries the same sections: Output, Config keys, Import where it applies, and Verify.
- The spec format, CLI, and configuration references are roughly half their former length. Detail that applies to one target moved onto that target's page.
- Docs pages keep a readable measure: the content column no longer narrows as the window widens, and prose lines stop near 83 characters.

### Fixed

- `agnostic-ai import crush` no longer lets a hook name steer where its spec is written. A Crush hook named `../escape` wrote outside the hooks directory; such a name now falls back to the deterministic filename and stays in the spec's `name:` field (#831).
- `outputs.claude.dir` moves rules and commands with the rest of the tool directory, and `{{rules_dir}}` and the other path variables resolve to the moved paths. With `dir: vendor/.claude`, rules landed in `.claude/rules/` at the project root while agents and settings moved, so one target wrote into two trees. A per-kind key such as `rules-dir` still wins. If you already set `dir`, the next full sync writes rules and commands under it and sweeps the old files as orphans; Claude Code auto-loads only a project-root `.claude/rules/`, so set `rules-mode: import` if it should still load them from the moved directory (#849).
- A nested `outputs.<target>.dir` such as `vendor/.claude` no longer collapses the managed `.gitignore` block to `/vendor/.claude/`, which ignored the whole tool directory including hand-authored files and the shareable `agent-memory/` store. The block now collapses at the generated subdirectory below the configured dir, as it already did for the default `.claude` (#846).
- The managed `.gitignore` block ignores Claude Code's `agent-memory-local/` instead of `agent-memory/`, matching the documented scopes: `memory: project` is shareable via version control, `memory: local` is not. A previously hidden `.claude/agent-memory/` starts appearing in `git status`, and an already tracked `agent-memory-local/` stays tracked until `git rm -r --cached` removes it, since a new ignore line does not untrack files. Nothing is deleted or committed automatically (#841).
- Long inline code, such as a file path, no longer pushes a docs page sideways.
- The sitemap lists `/docs/targets/` and every target page again, after the reference was split.
- Search works against a local `zola serve`, which appends a live-reload script to the index.
- Phone layouts meet minimum sizes: tap targets reach 32px and no text renders below 11px.

## Upstream CLI and model news {#upstream}

Every item below was opened on its primary vendor page on 2026-09-18. Upstream availability is not agnostic-ai support; each item names its support state.

### The Antigravity agent model changes its tool contract

**Product:** Gemini API, Antigravity agent model. **Source date:** 2026-09-17. **State:** watch.

`antigravity-preview-09-2026` replaces `antigravity-preview-05-2026`. Tool-call parameters "use PascalCase instead of snake_case", and file edits become "line-range replacements instead of full rewrites". The older model "shuts down on October 5, 2026", so code calling that API directly has three weeks to migrate. Source: [Gemini API changelog](https://ai.google.dev/gemini-api/docs/changelog). This is the agent model behind the API, not the Antigravity editor's project configuration, which is what the [Antigravity target](@/docs/targets/antigravity.md) writes. Nothing agnostic-ai emits changes shape.

### Cline changes the default model for 44 providers

**Product:** Cline v4.1.19. **Source date:** 2026-09-17. **State:** watch.

"The resolved default model changes for 44 providers, most of them landing on DeepSeek V4.1 Flash", and "Cline Pass now defaults to a model from your subscription rather than a free one". A project that never pinned a model gets a different one, and possibly a billed one, on the next run. Source: [Cline v4.1.19](https://github.com/cline/cline/releases/tag/v4.1.19). The [Cline target](@/docs/targets/cline.md) emits rules, agents, skills, and workflows, and models no default-model field, so a spec cannot pin this for you.

### Goose removes CLI planning mode and recipe auto-generation

**Product:** Goose v1.51.0. **Source date:** 2026-09-17. **State:** watch.

The release removes planning mode from the CLI and removes the create-recipe command. The second is a safety fix: "session-generated recipes copied globally enabled extension configuration directly into YAML. This could include inline environment values, HTTP headers, credential-bearing URLs, and extensions that were not active in the captured session." Manual recipes are untouched, "including manual creation, importing, editing, validation, execution, scheduling, and custom recipe slash commands". Sources: [Goose v1.51.0](https://github.com/block/goose/releases/tag/v1.51.0), [block/goose#11942](https://github.com/block/goose/pull/11942). The [Goose target](@/docs/targets/goose.md) emits agents, hooks, and skills, none of which travel through a generated recipe.

### Kilo Code removes KiloClaw and the local-review aliases

**Product:** Kilo Code v7.7.3. **Source date:** 2026-09-17. **State:** watch.

Removed: "the VS Code chat panel and sidebar button, the `/kiloclaw` TUI command and chat view, the Kilo Chat client and token handling, and the `kilo.claw.status` and `kilo.claw.chatCredentials` gateway endpoints". The `/local-review` and `/local-review-uncommitted` aliases are gone; "use `/review` with its scopes instead". A team with either alias in a runbook or a command spec needs to update it. Source: [Kilo Code v7.7.3](https://github.com/Kilo-Org/kilocode/releases/tag/v7.7.3).

### Three CLIs harden sandboxes and process execution

**Product:** Gemini CLI v0.60.0, Codex CLI rust-v0.155.0, Cline v4.1.19. **Source dates:** 2026-09-15, 2026-09-17, 2026-09-17. **State:** watch.

Gemini CLI v0.60.0 is a concentrated security release: it isolates the temporary directory for the macOS Seatbelt sandbox and the settings directory in sandbox containers, hardens "path resolution and boundary validation in extension loader", removes a "hardcoded Google CrUX API key in chrome-devtools-mcp", prompts "for consent on environment changes", enforces "strict permission and ownership checks on system-wide configuration paths", mitigates an "NTFS 8.3 short name (SFN) path", and enforces "envelope metadata provenance for untrusted tool outputs". Codex CLI "blocked Windows-process escapes from restricted WSL sandboxes" and "hardened brokered shell snapshots against credential exposure". Cline fixed a Windows execution path where "opening a repository that contains a file named `rg.exe`, `git.exe`, or `powershell.exe` no longer runs that file in place of the real program". All three are worth updating for, and none of them is a configuration surface agnostic-ai writes. Sources: [Gemini CLI v0.60.0](https://github.com/google-gemini/gemini-cli/releases/tag/v0.60.0), [Codex rust-v0.155.0](https://github.com/openai/codex/releases/tag/rust-v0.155.0), [Cline v4.1.19](https://github.com/cline/cline/releases/tag/v4.1.19).

### New provider and model options need no spec change

**Product:** Codex CLI rust-v0.155.0, OpenHands v1.19.0. **Source dates:** 2026-09-17, 2026-09-16. **State:** supported.

"Amazon Bedrock can now obtain AWS credentials from configured commands, with caching, expiration-based refresh, and authentication recovery". A `[model_providers.*]` block carrying that configuration round-trips verbatim through the Codex overlay, so it survives a sync today. OpenHands v1.19.0 adds GPT-6 Astra; the OpenHands agent file takes `model` as a free-form string, so naming it needs no adapter change. Sources: [Codex rust-v0.155.0](https://github.com/openai/codex/releases/tag/rust-v0.155.0), [OpenHands v1.19.0](https://github.com/OpenHands/OpenHands/releases/tag/v1.19.0).
