## Upgrading from v0.74.0 {#actions}

Stop any running `sync --watch` before changing version pins or installing. Use your existing install method. A standalone binary on macOS or Linux can install this exact release without loading the project's configuration:

```bash
agnostic-ai upgrade --version v0.75.0
```

Before syncing with the new binary, update an existing exact `requires` pin and any release-pinned schema comment in `agnostic-ai.yaml`, regardless of how the binary was installed:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/Chemaclass/agnostic-ai/v0.75.0/docs/schemas/config.schema.json
requires: "0.75.0"
```

For a project dependency, make those config edits before updating the dependency and lockfile with your package manager, for example:

```bash
pnpm add -D --save-exact agnostic-ai@0.75.0
# npm alternative: npm install -D --save-exact agnostic-ai@0.75.0
```

Add `-w` to the pnpm command only when the dependency belongs at the workspace root. Edit the configuration before installation if your project's postinstall runs sync, so the new binary does not encounter the old exact pin. These edits are manual. Preserve a deliberate minimum or range when it already accepts v0.75.0. A schema URL controls editor validation; `requires` controls which binary may run.

A global npm install uses `npm install -g agnostic-ai@0.75.0`. Other package-manager installs upgrade through their manager. For a Windows standalone install, the PowerShell installer accepts `-Version v0.75.0`. See [installation](@/docs/installation.md) for the other channels.

After installing, check the version, regenerate and review the outputs:

```bash
agnostic-ai --version
agnostic-ai sync
agnostic-ai lint
agnostic-ai sync --check
```

Use your local runner, such as `pnpm exec agnostic-ai`, for a project dependency. Commit the updated configuration and lockfile, plus generated files your project tracks. Claude users should review the new `.worktreeinclude`; projects sharing `AGENTS.md` should also review the shorter `CLAUDE.md` described below.

## What agnostic-ai changed

### Patched binaries and verifiable release archives

Release binaries move from Go 1.26.0 to Go 1.26.8. The project's vulnerability scan found reachable standard-library vulnerabilities in the previous binaries, including certificate-validation code used by the HTTPS upgrader. Moving to the newer toolchain includes the intervening security fixes. The Go project's [release history](https://go.dev/doc/devel/release) records those patches; [v0.75.0's changelog](https://github.com/Chemaclass/agnostic-ai/blob/v0.75.0/CHANGELOG.md#v0750---2026-09-29) records the binary upgrade and new CI gate.

Every release archive now has an SPDX software bill of materials (`.sbom.json`) and signed build provenance. After downloading your OS and CPU archive, verify its provenance with GitHub CLI:

```bash
gh attestation verify agnostic-ai_linux_amd64.tar.gz --repo Chemaclass/agnostic-ai
```

Replace the filename with the archive you downloaded. `agnostic-ai.intoto.jsonl` on the release page contains the attestation bundle. A checksum confirms that the download matches the release; provenance verifies its build identity. Both installers now stop if they cannot verify the checksum. To require provenance too, set `AGNOSTIC_AI_VERIFY_ATTESTATION=1` for `install.sh`, or pass `-VerifyAttestation` to `install.ps1`; this optional check needs GitHub CLI. The [verification guide](@/docs/verify-a-release.md) includes the full download and verification steps.

### Commit only the outputs a target needs

`gitignore.commit` now accepts `<target>:<kind>`. This lets a repository keep configuration needed by a remote tool while local tools regenerate their own copies:

```yaml
gitignore:
  enabled: true
  commit:
    - cursor:reviews
    - cursor:environments
```

These entries select the Cursor review and environment outputs. An unqualified kind still selects that kind across targets. Lint warns with LINT017 when an entry names a target the project has not enabled.

With Claude Code enabled, the managed Git ignore block also feeds `.worktreeinclude`, so new Claude worktrees receive ignored generated configuration and the local spec layer. Keep this file tracked when worktrees need those files. To opt out of generating its managed block:

```yaml
gitignore:
  enabled: true
  worktree-include: false
```

### Catch native configuration left on older branches

`sync --check --against` now catches hand-written configuration that Git tracks inside a folder the managed block ignores. For example, an older branch can still carry `.cursor/skills/review/SKILL.md` after the project has moved skills into `.agnostic-ai/`. The check names the native file and the import command that can adopt it:

```bash
agnostic-ai sync --check --against HEAD
```

Resolve that source-of-truth conflict before merging, rather than assuming an ignored folder cannot contain tracked files. Import also keeps separate environment files scoped to their original tools when several tools have one, and standard `SKILL.md` output now retains the Agent Skills `license` field.

### Claude Code and Cursor share instructions without duplication

When another enabled target writes root `AGENTS.md`, generated root `CLAUDE.md` now imports it with `@AGENTS.md` and keeps only Claude-specific instruction blocks. Cursor reads both files, so the shared body no longer loads twice. Keep shared instructions in `.agnostic-ai/AGNOSTIC_AI.md` and use `::target claude` blocks for text Claude needs separately. Review and commit the generated change if your project tracks these files.

### Cursor skills reach each opened app workspace

Cursor loads skills from the workspace it opens. A root skill can now request additional copies for app workspaces using `workspaces` in its frontmatter. For example, `.agnostic-ai/skills/review-api/SKILL.md` can contain:

```markdown
---
name: review-api
description: Review API contracts and compatibility.
workspaces: [apps/api, apps/web]
---

Check request validation, error responses and compatibility with callers.
```

Sync keeps the root `.cursor/skills/review-api/` and copies the skill and bundled assets into each listed app's `.cursor/skills/review-api/`. This addition applies to root skills; a skill already scoped by its source layout keeps that scope. A skill's `scope:` frontmatter key has no effect and now gets LINT018. Use `workspaces` for extra workspace copies instead.

The [complete release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.75.0) cover the remaining fixes.

## What changed in the targets

### Amp medium mode changes upstream

Amp announced on **September 28, 2026** that Opus 5.5 replaces GPT-5.6 Sol in its default `medium` mode. The **ChatGPT Only** preset keeps GPT-5.6 Sol; Amp's Tune Modes controls that selection. If you compare results or costs across the upgrade, check the actual Amp mode and preset. This is an upstream model-routing change, with no new agnostic-ai field or adapter output in v0.75.0. [Amp's announcement](https://ampcode.com/news/opus-5.5).
