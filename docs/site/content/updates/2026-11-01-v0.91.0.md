## Highlights {#highlights}

- **Breaking:** an empty `targets` list keeps generated files. Run `agnostic-ai sync --allow-empty-targets` to remove them. See [sync and cleanup](@/docs/cli-reference/sync.md).
- **Context size** is the first tab in `agnostic-ai serve`. It shows what each tool loads at startup and on demand, with a fix and an agent prompt to copy for each source.
- **Settings** turns coding tools on and off per project and picks the editor that file links open.
- **Authority** edits and removes permission rules with a preview. **Tools** saves a native-only MCP server as a spec.
- **Safer sync:** it stops instead of overwriting files it cannot read, keeps your `.gitignore` and Claude settings entries, and writes remote MCP servers that work.

## Upgrading from v0.90.0 {#actions}

Stop any running `agnostic-ai sync --watch` process before you update the install or the project config. Installing the package does not run sync, but a project `postinstall` script, the automatic update offer, `agnostic-ai upgrade --requires` and `agnostic-ai sync` do. Make the changes below that apply to you before any of them.

- **Review empty target lists.** With `targets: []`, sync now warns and keeps generated files. Add a target to resume sync, or run `agnostic-ai sync --allow-empty-targets` to remove generated files. `sync --check` fails while generated files remain. With a missing sync state, run the removal command too before a plain check can confirm the result. See [sync and cleanup](@/docs/cli-reference/sync.md).
- **Fix repeated YAML keys.** A repeated key in a nested map is now a parse error with a line number. Remove the duplicate and keep the value you want. An empty local key or model tier keeps the shared value. To clear a group where supported, use an empty object. See [configuration](@/docs/configuration.md).
- **Check shared skill folders.** Qwen now imports `.agents/skills/`. With Qwen selected, Amp, Crush, Warp and Zed stop writing agents as skills. If you need those agents, set the other tool's `outputs.<tool>.skills-dir` to a separate folder. See [Qwen output](@/docs/targets/qwen.md).
- **Update Kimi MCP executors.** Remove `x-kimi.executor: kaos` or choose `local` for a server that should run locally. Sync now rejects unsupported executors. See [Kimi MCP settings](@/docs/targets/kimi.md).
- **Choose Vibe sampling for existing global servers.** If an earlier sync adopted a server with `sampling_enabled: true` from a spec without sampling, set `x-vibe.sampling_enabled` before global sync: `true` keeps it, `false` turns it off. See [Vibe global sync](@/docs/targets/vibe.md).

Install through your package manager. For a global npm install:

```bash
npm install -g agnostic-ai@0.91.0
```

Run `agnostic-ai upgrade --requires` in the project to update its requirement and schema URL, then sync. A minimum stays a minimum, an exact requirement stays exact, and a range becomes a minimum. Review the changes and run `agnostic-ai sync --check` before you restart watch. See [upgrade options](@/docs/cli-reference/upgrades.md#upgrade).

## What agnostic-ai changed

### Keep files and surface unsafe input

Plain sync and every watch pass keep generated files when the target list is empty. Removing one tool from a nonempty list still cleans up that tool's output. Sync reports unreadable JSON settings and state-write failures instead of replacing or losing data. Git ignore files are written whole, and a failed pack fetch keeps the installed content. See [sync behavior](@/docs/cli-reference/sync.md) and [packs](@/docs/packs.md).

### Review context and configure tools in the browser

Run `agnostic-ai serve --open` and open **Context > Context size** to see what each source adds at startup, inspect a file's scoped context, and copy a review prompt. **Settings > Coding tools** saves shared or personal target choices for the next sync. Settings also sets editor links, and **Open global settings** creates the global folder if it is missing. See the [web interface](@/docs/cli-reference/inspect.md#serve).

### Preserve more settings on import and sync

Cline agent settings and OpenHands agent skills survive native import followed by sync. Gemini MCP OAuth options, including private-network opt-in, round-trip without putting literal credentials in specs. Kiro settings can write a workspace default model to `chat.defaultModel`. Global voice settings now cover Qwen, Gemini, Grok, Vibe, Kiro and Warp where supported. See [Cline](@/docs/targets/cline.md), [OpenHands](@/docs/targets/openhands.md) and [settings by target](@/docs/spec-format/settings.md).

### Check hooks and MCP servers more reliably

MCP server listing respects its timeout when a detached child keeps stderr open. Hook commands keep home, environment-variable and absolute paths, and Windows hook timeouts report the right result. Import and sync keep Crush's supported lifecycle events and reject invalid matchers. See [hook reference](@/docs/spec-format/hook-reference.md) and [MCP configuration](@/docs/spec-format/mcps.md).

See the [full release notes](https://github.com/Chemaclass/agnostic-ai/releases/tag/v0.91.0) for the remaining fixes.

## What changed in the targets

### Project defaults and imported agents

[Kiro's settings reference](https://kiro.dev/docs/cli/reference/settings/), checked November 1, documents a default model and workspace settings. This release writes a settings spec's Kiro model to `.kiro/settings/cli.json`. Use a model ID Kiro accepts.

[Cline v4.1.26's agent parser](https://github.com/cline/cline/blob/v4.1.26/sdk/packages/core/src/extensions/tools/team/configured-agent-config.ts), released October 26, accepts tools, skills, provider, model and iteration settings. Import now keeps those settings for sync. [OpenHands documents named skills in file-based agents](https://docs.openhands.dev/sdk/guides/agent-file-based); import now keeps those skill names too. Both sources were checked November 1. Import and sync output were tested against the released Cline parser and OpenHands SDK 1.59.0 (released October 28).

### Shared skill paths and workspace rules

[Qwen Code's skill guide](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/), checked November 1, documents project and user skill locations. This release imports the shared `.agents/skills/` path as well as `.qwen/skills/`.

[Antigravity's rules guide](https://antigravity.google/docs/rules/), checked November 1, says it does not load rules below the workspace folder. A scoped rule written to a subfolder needs a workspace rooted at that folder. Its [plugin guide](https://antigravity.google/docs/build-plugins) documents `mcp_config.json` at the plugin root, and this release fixes the guide and note for that path. Native discovery was not tested in this audit.

[Junie's CLI reference](https://junie.jetbrains.com/docs/environment-variables.html) documents a custom guidelines filename. [Qoder CLI](https://docs.qoder.com/cli/Skills) and its [IDE extension](https://docs.qoder.com/extensions/skills) describe different skill conflict precedence. The target guide now names which surface each applies to. Native precedence was not tested.

### Native hooks and OAuth

Crush v0.99.0, released October 29, documents 13 lifecycle hooks, and this release can import and sync them. Gemini CLI v0.66.0, released October 27, documents `oauth.allowPrivateNetwork` as an explicit MCP server opt-in. This release keeps non-secret native OAuth options through import and sync. See the [Crush release](https://github.com/charmbracelet/crush/releases/tag/v0.99.0) and [Gemini CLI release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.66.0).
