# Adding an adapter

[Contributor docs](README.md)

Add a new AI CLI target (`foo`).

## 1. Create the package

`internal/adapters/foo/foo.go`:

```go
package foo

import (
    "github.com/chemaclass/agnostic-ai/internal/adapters/internal/emit"
    "github.com/chemaclass/agnostic-ai/internal/config"
    "github.com/chemaclass/agnostic-ai/internal/spec"
)

const (
    target         = "foo"
    defaultOutFile = "FOO.md"
)

var caps = emit.Capabilities{
    Target:   target,
    Supports: []spec.Kind{spec.KindAgent, spec.KindSkill, spec.KindRule},
}

type Adapter struct{}

func New() *Adapter { return &Adapter{} }

func (Adapter) Name() string { return target }

func (Adapter) Capabilities() []spec.Kind { return caps.Supports }

func (Adapter) Emit(sess *emit.Session, b spec.Bundle, cfg *config.Config, dryRun bool) error {
    if err := emit.ReportUnsupported(caps, b, cfg.OnUnsupported); err != nil {
        return err
    }
    return sess.MergedDocument(b, emit.MergedOpts{
        OutFile:            emit.OutputFile(cfg, target, defaultOutFile),
        Title:              "FOO.md",
        Intro:              "Generated by agnostic-ai.",
        AgentSectionPrefix: "Agent: ",
    }, dryRun)
}
```

To write one file per rule instead of one combined document, replace `sess.MergedDocument` with `sess.RulesDirectory` (see Cursor / Cline / Windsurf). Both honor `spec.Entry.Scope`.

## 2. Register

`internal/adapters/adapter.go`:

```go
import "github.com/chemaclass/agnostic-ai/internal/adapters/foo"

var registry = map[string]Adapter{
    "foo": foo.New(),
}
```

Add to default targets in `internal/config/config.go` (`DefaultTargets()`) and to the complete target list in `internal/cli/init_interactive.go` (`allTargets`). These two lists are separate; keep them in sync.

## 3. Document

- Add a row to `docs/site/data/capabilities.toml` (the supported-features table, with `href` pointing at the new page) and write the per-target page at `docs/site/content/docs/targets/<target>.md`.
- Update `README.md` supported-target summary and `docs/site/content/docs/configuration.md`.
- Add an `[Unreleased]` entry in `CHANGELOG.md`.
- If config struct fields or tags change, run `go run ./cmd/schemagen`.
- Regenerate the saved expected output files and supported-target lists listed in `.agnostic-ai/rules/capability-fixtures.md`.

## 4. Wire config

Use the shared helpers to resolve output paths:

| Helper | Use for |
|---|---|
| `emit.OutputFile(cfg, target, fallback)` | single-document outputs |
| `emit.OutputDir(cfg, target, fallback)` | parent directory |
| `emit.OutputRulesDir(cfg, target, fallback)` | directory containing one file per rule |
| `emit.OutputRulesFile(cfg, target, fallback)` | merged rules file |
| `emit.OutputMCPFile(cfg, target, fallback)` | MCP configuration output |
| `emit.OutputAgentsDir(cfg, target, fallback)` | per-agent files |
| `emit.OutputSkillsDir(cfg, target, fallback)` | per-skill files/folders |
| `emit.OutputCommandsDir(cfg, target, fallback)` | slash-command directories |
| `emit.OutputInstructionsDir(cfg, target, fallback)` | Copilot-style scoped rules |
| `emit.EmitSkillsAsCommands(cfg, target)` | opt-in flag for skills-as-commands |

New field on `config.Output`? Add once, reuse.

## 5. Shared helpers

Use the `sess` passed to `Emit` for file writes, migrations, and capture checks.

- `emit.GroupRulesByScope(rules)` + `emit.RouteScope(r)`: write rules to the correct `<scope>/AGENTS.md` / `<scope>/GEMINI.md` files for each folder.
- `emit.WriteSection(sb, heading, e)`: inlined `### heading`. `emit.WriteReference(sb, e, sourcePath)` points when the definition lives elsewhere.
- `emit.WriteTOMLString` / `WriteTOMLMultiline` / `WriteTOMLStringArray` / `EscapeTOMLBasic`: write TOML values.
- `emit.Frontmatter(meta)`: write the YAML fields at the start of a Markdown file (frontmatter).
- `emit.ResolveMeta(meta, target)`: apply `x-<target>` overrides as top-level keys.
- `sess.MigrateLegacyFile(cfg, target, legacyName, defaultNewPath, dryRun)`: rename old outputs across releases.
- `sess.IsCapturing()`: check whether output is being collected for comparison before changing files outside `WriteFile`.

## 6. Tests

`internal/adapters/foo/foo_test.go`:

```go
func TestEmit_WritesExpectedFile(t *testing.T) {
    dir := t.TempDir()
    testutil.Chdir(t, dir)

    entries := []spec.Entry{
        {Kind: spec.KindRule, Name: "r1", Path: "rules/r1.md", Body: "rule body"},
    }
    if err := New().Emit(emit.NewSession(), spec.NewBundle(entries), &config.Config{}, false); err != nil {
        t.Fatal(err)
    }
    got, err := os.ReadFile(filepath.Join(dir, "FOO.md"))
    if err != nil {
        t.Fatal(err)
    }
    for _, want := range []string{"rule body", "<!-- source: rules/r1.md -->"} {
        if !strings.Contains(string(got), want) {
            t.Errorf("missing %q in %s", want, got)
        }
    }
}
```

Extend `internal/adapters/adapter_test.go` so the registry test sees the new name.

## 7. Unsupported kinds

Leave unsupported types out of `caps.Supports`. `emit.ReportUnsupported` warns or returns an error according to the user's `on-unsupported` setting.

## 8. MCP propagation (optional)

MCP (Model Context Protocol) connects coding tools to external services. If the target has a project-local MCP configuration:

```go
return sess.WriteMCPFile(b.MCPs, emit.MCPSchemaServersMap,
    emit.OutputMCPFile(cfg, target, defaultMCPFile), dryRun)
```

Built-in schemas:

- `MCPSchemaServersMap`: `{"mcpServers": {...}}` (Claude, Cursor, Warp)
- `MCPSchemaVSCodeServers`: `{"servers": {...}}` with `type` per server (Copilot / VS Code)

For formats that differ from these schemas, write target-specific output: Codex TOML, Gemini `httpUrl`, Amp `amp.mcpServers` dotted key, Zed `context_servers`, OpenCode `mcp`, Continue one-YAML-per-server. See each adapter. Use `sess.MergeJSONFile` to preserve unrelated user keys. Use `emit.OutputMCPDir` for one-file-per-server.

## 9. Hooks (optional)

Emit alongside MCPs in the target's project configuration file (Codex: `.codex/hooks.json`; Gemini: `.gemini/settings.json`). Group by `Meta["event"]`; skip entries without one. Keep event names unchanged.

## 10. Keeping the adapter true

An adapter follows the vendor's configuration format at the time it is written. Vendors can move paths or rename keys. Sync can still succeed while writing files the tool no longer reads. Check both sources below:

- Add the target's doc and changelog URLs to
  `.agnostic-ai/skills/target-audit/references/sources.md`, with a
  `watch:` line naming the parts most likely to change. This is not
  optional: `tests/integration/target_audit_sources_test.go` fails until
  the new target has a section, so an adapter cannot merge un-audited.
  Follow that file's required URL line format, because `scripts/docfetch.sh`
  parses those two lines and `scripts/docfetch_test.sh` fails when a
  target resolves no docs URL or no changelog URL. Run
  `scripts/docfetch.sh <target>` once and commit the new rows it adds to
  `scripts/target-audit/sources.lock`.
- `scripts/target-facts.sh <target>` prints what the repo currently
  claims (capabilities, default paths, package doc, the
  `targets/_index.md` rows and the target's page). Compare that output with the vendor documentation.

The `target-audit` skill runs that comparison across every registered
target in parallel and files an issue for each confirmed difference. Run it after
adding an adapter to confirm the new rows read correctly.

## Conventions

- Adapter packages never import other adapters. Share via `internal/adapters/internal/emit`.
- Stateless adapters, with no mutable instance fields; construct with `New()`.
- Keep Markdown header fields unchanged unless the target needs a different format (for example, Cursor `.mdc`).
- Generated files belong in `.gitignore` (or rely on `gitignore.enabled: true`).
